# Скорость портирования

По умолчанию разделы упаковываются двумя независимыми задачами. На машине
с одним CPU используется одна задача; на Linux число задач также снижается
до одной, если доступно менее 4 ГиБ памяти. Число задач можно задать в `bin/port_config` через `pack_jobs`
либо переменной окружения:

```shell
PORT_PACK_JOBS=4 bash ./port.sh /path/to/base.zip /path/to/donor.zip
```

Допустимы `auto` и числа от 1 до 32. `PORT_PACK_JOBS=1` включает
последовательную упаковку. Большее число задач увеличивает одновременные
обращения к диску и потребление памяти; для HDD и небольших машин обычно
подходит одна задача. Автоматический режим ограничен двумя задачами.

Каждая задача сначала обновляет собственные `fs_config` и `file_contexts`,
восстанавливает специальные правила Android 17 для vendor, затем создаёт
образ через временный файл. Ошибка останавливает запуск следующих задач;
уже запущенные задачи завершаются до выхода из этапа. Следующий этап
получает управление только после успешной упаковки всех разделов.
Журналы сохраняются в `build/logs/pack/<раздел>.log`, а время каждого раздела
выводится после его завершения. Блокировка сборки удерживается до окончания
работы фоновых задач, в том числе при прерывании скрипта.

Для mkfs.erofs с поддержкой `--workers` CPU распределяются между задачами.
Старые версии без этой опции запускаются с прежними аргументами. Аналогично
ограничивается число потоков Rust-патчеров через `RAYON_NUM_THREADS`; явно
заданное пользователем значение сохраняется. Алгоритм и уровень сжатия
EROFS остаются `lz4hc,12`.

Дополнительные изменения:

- Перед EROFS больше нет отдельного обхода всего дерева ради неиспользуемого
  размера. Для EXT4 размер обычных файлов считается одним Python-процессом,
  без запуска `stat` для каждого файла. Символические ссылки не обходятся;
  размеры разреженных файлов считаются логически, как прежде.
- Копии сырых образов используют GNU `cp --reflink=auto --sparse=always`.
  На файловых системах с reflink копирование не требует записи всех блоков;
  в остальных случаях выполняется обычное копирование. На системах без
  этих опций используется прежний `cp`. Жёсткие ссылки для образов не
  применяются: изменения рабочего образа не должны менять кэш.
- При `PORT_LOW_DISK=true` не записывается дополнительный кэш образов,
  который удалялся в том же запуске после распаковки. Локальный кэш в
  обычном режиме сохраняется. При упаковке Fastboot базовые firmware и boot
  переносятся в выходной каталог до удаления `build/baserom`.
- GitHub Actions устанавливает Playwright и Chromium только при поиске ROM
  по названию модели. Для прямых HTTP/HTTPS-ссылок эта установка пропускается.

Проверки, не требующие ROM или телефона:

```shell
python3 -m unittest discover -s tests -p test_port_performance.py -v
```

Для сравнения полного времени используйте одну пару ROM и одинаковый режим
кэша, меняя `PORT_PACK_JOBS=1` на `PORT_PACK_JOBS=auto`. Отдельно сравнивайте
первый запуск и повторную сборку: прогретый кэш и загрузка файлов заметно
влияют на результат. Время полного порта зависит также от CPU, диска,
размеров разделов и сложности APK-патчей.
